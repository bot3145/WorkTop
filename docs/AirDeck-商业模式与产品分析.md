# AirDeck 商业模式与产品分析

> 研究对象：[AirDeck · 现代 Windows 原生全屏启动台](https://air.appwk.cn/airdeck)（AppAir Studio）
> 调研时间：2026-11-10
> 说明：本文基于官网公开页面、产品截图、开发者发布文章与公开搜索资料整理；未获取 AirDeck 的内部经营数据。文中标注“推断”的部分为分析判断，不代表官方事实。

---

## 0. 结论摘要

1. **AirDeck 不是“AI 演示工具”**，而是一款 Windows 原生全屏启动台 + 桌面常驻 Dock。它与海外同名产品 AirDeck（文档演示 SaaS）、AirDeck（手机遥控器）不是同一款产品。
2. **当前商业模式是“免费工具获客，Pro 作为后续变现接口”**：官网只提供免费下载，没有公开价格页；但设置界面已经出现「专业版体验」标识和「账户」入口，说明团队在为后续 Pro 版/账号体系留口子。
3. **它真正卖的不是“启动器功能”，而是三种感受**：桌面更整洁、操作更顺手、系统更轻盈。官网用 `~25MB`、`<15ms`、`零广告`、`100% 本地` 这些可验证承诺建立信任。
4. **产品矩阵是它的隐形增长杠杆**：AppAir 同时做归纳星（文件整理）、AirDeck（启动台）、AirPlayer（播放器），三个工具共享“原生、纯净、轻量”的品牌心智，可以互相导流。
5. **最值得借鉴的是“产品可演示性 + 工程可信度 + 内容分发”**，而不是照搬功能。AirDeck 的每个卖点都能在 5 秒内被看懂：按下快捷键、输入 `wx`、微信秒开、Dock 浮现、3D 窗口展开。
6. **抖音没有“视频号”**：视频号是微信生态的产品；抖音对应的是短视频、直播、抖音号与兴趣电商。两者可以分别用于“拉新”和“信任沉淀”，下文分开分析。
7. **对 WorkTop 的启示**：不要把自己做成“又一个启动器”；应强化“桌面工作台 + 情绪化吉祥物 + 本地数据主权”的差异，采用“免费核心 + 服务/便利型 Pro”而不是硬性功能阉割。

## 2. 产品定位与目标用户

### 2.1 一句话定位

> 给 Windows 一个更优雅、更原生、更轻量的应用启动与桌面组织方式。

AirDeck 用“全屏启动台”替代“桌面图标 + 开始菜单 + 任务栏”之间的来回寻找，再用“常驻 Dock”承接高频启动，用“多场景”承接工作/娱乐不同状态。

### 2.2 目标用户

| 用户群 | 痛点 | AirDeck 的吸引力 |
|---|---|---|
| Windows 重度用户 | 安装软件多、图标乱、开始菜单难找 | 全屏网格 + 拼音快搜 |
| 开发者 / 设计师 | 工具多、切换频繁、讨厌 Electron 臃肿 | 原生 .NET、低内存、<15ms 呼出 |
| 多屏 / 扩展坞用户 | 副屏呼出位置错乱 | 跟随光标所在屏幕展开 |
| 桌面美学爱好者 | 想让桌面更“macOS 感” | 液态玻璃 Dock、模糊壁纸、统一视觉 |
| 隐私敏感用户 | 反感遥测、广告、后台常驻 | 100% 本地、零广告、零守护进程 |
| 游戏 / 影音用户 | 全屏应用切换麻烦 | 托盘应用唤醒、Dock 状态点、音乐悬浮球 |

### 2.3 用户真正雇佣它完成的任务（JTBD）

1. “我现在就要打开某个软件，不想找。”
2. “我的桌面太乱了，但我又不想手动整理。”
3. “我工作和娱乐用的是同一台电脑，布局应该能切换。”
4. “我想要一个看起来高级、但不吃内存的桌面工具。”

## 3. 商业模式拆解

### 3.1 收入结构：目前是“免费 + Pro 预留”，尚未完全公开变现

**可观察到的事实：**

- 官网首页与产品页都只提供“免费下载”，没有价格表、购买按钮、订阅说明。
- 产品设置界面左上角显示「AirDeck 专业版体验」，左侧导航包含「账户」。
- 官网强调“零广告”“零静默常驻”“100% 纯本地”，明确不走广告/数据变现。
- AppAir 产品矩阵中的归纳星标注“已上线 · 免费”，AirPlayer 标注“压测打磨中”。

**由此可以推断：**

| 收入来源 | 可能性 | 说明 |
|---|---|---|
| Pro 买断/授权 | 高 | 本地工具最适合一次性付费；设置页已有 Pro 入口 |
| Pro 订阅 | 中 | 若后续加入云同步、AI、在线模板，订阅更合理 |
| 大版本付费升级 | 中 | 例如 2.0 / 3D 窗口管理作为付费升级 |
| 企业/团队授权 | 中低 | 当前产品偏个人，但可做批量部署与定制 |
| 定制开发/外包 | 中 | AppAir 是工作室型团队，产品可当作能力展示 |
| 广告/数据 | 极低 | 与品牌承诺直接冲突，基本可排除 |

> 结论：AirDeck 现在更像“先用免费产品做规模和品牌，再决定 Pro 的边界与价格”。这是一种典型的 **product-led growth（产品驱动增长）** 早期策略。

### 3.2 为什么选择“免费 + 本地优先”

1. **边际成本极低**：没有云端推理、没有大规模存储，下载与更新是主要成本。
2. **信任成本极低**：不需要注册、不上传数据，“下载即用”降低尝试门槛。
3. **传播成本极低**：免费工具更容易被推荐、被搬运、被做成“Windows 必装”合集。
4. **为 Pro 留出空间**：基础功能免费建立习惯，高级能力（3D 预览、场景、个性化、账户同步）再收费。

代价是：**用户对桌面工具的付费预期很低**。Windows 上大量同类工具免费或开源（PowerToys Run、Flow Launcher、Listary、uTools 等），AirDeck 必须靠“设计 + 原生性能 + 品牌”做出溢价。

### 3.3 成本结构

| 成本项 | 特点 |
|---|---|
| 研发 | 主要成本；原生 Win32/WPF 开发门槛高，3D 预览、窗口捕获、托盘唤醒都是硬活 |
| 设计 | 高投入；产品差异化很大程度来自视觉与动效 |
| 分发/更新 | 官网直链 + 更新服务器，成本可控；无应用商店 30% 分成 |
| 支持 | 独立软件常见隐性成本；Windows 版本/显卡/多屏兼容问题多 |
| 云服务 | 基本为零；这是“本地优先”带来的结构性优势 |
| 合规/签名 | 代码签名证书、SmartScreen 信誉积累，是容易被忽略的固定成本 |

### 3.4 获客与分发

**已观察到的渠道：**

- 官网 SEO/品牌站：产品页信息密度高，像一份“工程说明书”。
- 微信公众号发布文章：开发者自述产品理念与功能，建立人格化信任。
- 产品矩阵互推：AirDeck 启动台里可以直接看到/启动自家“归纳星”，AppAir 官网也有矩阵入口。
- 直接下载：不依赖 Microsoft Store，减少上架审核与分成，但需要自己解决信任与安装引导。
- 口碑/合集：这类“桌面美化/效率工具”很容易被 B 站、抖音、小红书、知乎的“Windows 必装”内容收录。

**推断的获客飞轮：**

```
免费工具 → 低门槛下载 → 桌面效果可截图/可拍视频
   ↑                              ↓
产品矩阵互推 ← 品牌信任 ← 内容传播/口碑
   ↓
Pro 转化 / 定制咨询 / 企业授权
```

### 3.5 转化路径设计

AirDeck 的转化不是靠弹窗，而是靠“体验落差”：

1. **首次使用**：`Alt + Space` 呼出，输入拼音首字母，应用秒开 → “确实快”。
2. **持续使用**：Dock 常驻、运行状态点、托盘应用唤醒 → 形成肌肉记忆。
3. **进阶需求**：多场景、个性化、3D 预览、配置迁移 → 产生“想要更多”的意愿。
4. **Pro 入口**：设置页「专业版体验」+「账户」→ 在用户已经认可价值后出现，而不是首次启动就拦截。

这比“下载前先注册/付费”的漏斗更温和，也更适合工具类产品。

### 3.6 商业模式画布

| 模块 | 内容 |
|---|---|
| 客户细分 | Windows 重度用户、开发者、设计师、多屏用户、桌面美学爱好者、隐私敏感用户 |
| 价值主张 | 更快找到并启动应用；更整洁的桌面；更原生的性能；更统一的视觉 |
| 渠道 | 官网、微信公众号、短视频/视频号、产品矩阵、口碑合集、直接下载 |
| 客户关系 | 开发者人格化沟通、社区反馈、版本更新、Pro 支持 |
| 收入来源 | Pro 授权（推断）、大版本升级、企业定制、可能的云服务 |
| 核心资源 | 原生开发能力、设计品味、品牌信任、产品矩阵、更新与分发基础设施 |
| 关键活动 | 产品迭代、内容创作、兼容性测试、用户支持 |
| 关键伙伴 | 代码签名/分发服务、支付服务、内容平台、可能的硬件/系统厂商 |
| 成本结构 | 研发、设计、支持、签名、带宽、支付手续费 |

### 3.7 护城河与风险

**可能的护城河：**

- **工程能力**：低层键盘钩子、WorkerW 桌面嵌入、Windows.Graphics.Capture、WPF 3D，这些不是简单套壳能复制的。
- **设计一致性**：从启动台到 Dock 到设置页，视觉语言统一，形成品牌识别。
- **信任资产**：“零广告、零后台、纯本地”是长期承诺，一旦建立就很难被大厂复制（大厂有商业化压力）。
- **产品矩阵**：多个工具共享同一批用户与同一套品牌心智。

**主要风险：**

| 风险 | 说明 | 应对 |
|---|---|---|
| 品类拥挤 | 启动器/桌面工具竞争者多，免费替代品强 | 强化设计、原生性能、场景化差异 |
| 付费意愿低 | 用户习惯免费工具 | Pro 卖“省时间/美感/进阶能力”，不卖基础功能 |
| Windows 兼容性 | 系统更新可能影响钩子、Dock、窗口捕获 | 自动化测试矩阵、灰度发布、快速回滚 |
| 安装信任 | 未知发布者/SmartScreen 拦截 | 代码签名、安装说明、用户评价、微软商店备选 |
| 单点依赖 | 独立开发者/小团队，更新节奏与支持能力有限 | 模块化、文档化、社区共建、控制功能范围 |
| 过度设计 | 3D 动效很酷，但可能拖慢高频操作 | 默认轻量，重效果可选开启 |

### 3.8 一个示例测算（非官方数据）

假设：下载量 10 万，Pro 转化率 2%，客单价 ¥99（一次性）：

```
100,000 × 2% × ¥99 = ¥198,000（毛收入，未扣支付/税费/支持成本）
```

敏感性：

| 下载量 | 转化率 | 客单价 | 毛收入 |
|---:|---:|---:|---:|
| 5 万 | 1% | ¥99 | ¥49,500 |
| 10 万 | 2% | ¥99 | ¥198,000 |
| 20 万 | 3% | ¥99 | ¥594,000 |

结论：**单靠一个免费启动台的 Pro 转化，收入天花板有限**。要放大，需要：
1. 更高频的使用场景（Dock 常驻、开机自启）；
2. 更强的 Pro 价值（3D 窗口、跨设备同步、团队配置）；
3. 更高客单价的 B 端服务（企业部署、定制、培训）；
4. 产品矩阵交叉销售。

## 4. 产品样式分析

### 4.1 启动台界面

从官网截图看，AirDeck 的主界面遵循“**壁纸即背景、内容即界面**”的思路：

- **全屏铺满**：不画窗口边框，直接把桌面壁纸高斯模糊后作为背景，应用网格浮在上面。
- **顶部居中搜索胶囊**：半透明深色底、圆角、左侧放大镜、右侧 `Alt + Space` 快捷键提示。
- **6 × 5 应用网格**：图标大、间距宽、名称小号白字带阴影；底部 5 个分页圆点。
- **右上角齿轮**：唯一常驻设置入口，避免顶部堆满按钮。
- **底部液态玻璃 Dock**：圆角矩形、磨砂透明、图标原色、运行应用下方有状态点。
- **信息层级**：搜索 > 应用图标 > 应用名称 > 分页/设置；没有多余装饰。

**设计语言关键词：** 原生感、玻璃拟态、低对比背景、彩色图标、克制留白、轻动效。

**优点：**

- 第一眼“高级”，适合截图传播。
- 图标保持原色，识别成本低。
- 搜索居中、键盘优先，符合高频操作。
- Dock 与启动台形成“浏览 vs 直达”的分工。

**代价：**

- 文字对比度依赖壁纸；浅色壁纸下白字可能发灰。
- 应用名截断（如 “Microsoft T...”），长名称识别受影响。
- 6×5 网格适合中量应用；应用极多时依赖分页/搜索。
- 对完全新手，缺少“分类/文件夹”的显性引导。

### 4.2 设置界面

- **深色双栏布局**：左侧品牌区 + 导航，右侧内容区。
- **品牌区**：AirDeck logo、产品名、`专业版体验` 小字。
- **导航**：通用 / 程序坞 / 外观与图标 / 布局与网格 / 小组件 / 动效与手势 / 应用管理 / 账户。
- **内容区**：分组卡片、行式设置项、右侧开关/下拉/按钮；蓝色强调色用于选中态和开关。
- **密度**：行高约 48–56px，信息不拥挤；危险操作（恢复默认）用低饱和红色。
- **文案**：口语化、解释性副标题（如“开机自启、全局快捷键、多显示器行为与检查更新”）。

**设计评价：**

- 成熟、克制、可信，像一个“认真做出来的原生软件”。
- 蓝色强调色与启动台的冷色背景一致，品牌统一。
- `专业版体验` + `账户` 是清晰的商业化接口，但目前缺少价格与权益说明，容易让用户产生“是不是要收费”的不确定感。

### 4.3 3D 窗口预览（路线图）

- 鼠标悬停 Dock 中运行应用 → 展开 Cover Flow 式 3D 卡片舞台。
- 窗口卡片有弧度景深、圆角、阴影、页码指示；右上角可关闭单窗口。
- 技术上使用 WPF Viewport3D + Windows.Graphics.Capture + DWM。
- 这是典型的“** wow 功能**”：不一定每天用，但非常适合做视频封面和传播素材。

**评价：** 3D 预览是差异化利器，但要防止“演示很酷、日常不用”。建议默认提供轻量 2D 预览，3D 作为可选增强。

### 4.4 官网样式

- 深色背景、超大标题、细体英文小标签、数字指标、全宽截图。
- 结构像“产品说明书”：规格、架构、路线图、下载。
- 用“~25MB / <15ms / 100% 本地 / 零广告”建立工程可信度。
- 这种“把技术参数当卖点”的写法，非常适合独立开发者产品。

## 5. 功能分析

### 5.1 功能地图

| 层级 | 功能 | 价值 | 备注 |
|---|---|---|---|
| 核心 | 全局快捷键呼出 | 高频入口 | 默认 `Alt + Space`，可自定义 |
| 核心 | 拼音首字母/全拼搜索 | 毫秒级找应用 | Trie 倒排索引，`wx` → 微信 |
| 核心 | 6×5 应用网格 | 一屏浏览 | 横向惯性翻页 |
| 核心 | 常驻 Dock | 高频直达 | 液态玻璃、运行状态点、托盘唤醒 |
| 核心 | 应用管理/图标 | 组织桌面 | 支持添加、分类、图标显示 |
| 进阶 | 多场景切换 | 工作/娱乐分离 | 独立布局，快捷键切换 |
| 进阶 | 多显示器跟随 | 副屏不误呼出 | 跟随光标所在屏幕 |
| 进阶 | 开机自启/自动收起 | 无感使用 | 设置项 |
| 进阶 | 时钟/系统监控小组件 | 桌面信息感知 | 翻页时钟、CPU/RAM |
| 进阶 | 音乐悬浮球 | 不切窗口控制播放 | 开发者文章提及 |
| 进阶 | 配置迁移 | 换机延续习惯 | 原子快照导出/导入 |
| 路线图 | 3D 窗口预览 | 多任务切换 | Cover Flow + 实时捕获 |
| 账户 | 账户/专业版 | 商业化 | 目前权益未公开 |

### 5.2 功能设计上的聪明之处

1. **键盘优先，而不是鼠标优先**：呼出后焦点直接在搜索，减少一次点击。
2. **拼音搜索贴合中文用户**：`wx`、`bdfy` 这种输入习惯，比英文搜索更高效。
3. **Dock 与启动台分工明确**：启动台负责“找”，Dock 负责“常用”。
4. **场景化而不是文件夹化**：工作/娱乐是用户能理解的心智，比“新建文件夹”更自然。
5. **把“轻”做成可量化卖点**：25MB、<15ms，让“原生”不再是一句空话。
6. **配置迁移**：提高换机/重装后的留存，是工具类产品常被忽略的留存点。

### 5.3 功能上的空白/机会

- 没有看到“应用使用频率/智能排序”的强推荐逻辑（可能藏在实现里）。
- 没有看到跨设备同步/账号体系的实际权益说明。
- 没有看到插件/扩展生态（对比 uTools、Raycast）。
- 没有看到团队/企业配置分发（对比企业软件部署）。
- 3D 预览尚未正式上线，当前仍是“期货”。

## 6. 抖音与视频号：两种完全不同的增长逻辑

> **概念校正：** 视频号是微信生态的产品；抖音没有名为“视频号”的产品，对应的是短视频、直播、抖音号与兴趣电商。两者不是同一套分发逻辑，不能混为一谈。

### 6.1 机制对比

| 维度 | 抖音（短视频/直播） | 微信视频号 |
|---|---|---|
| 流量逻辑 | 兴趣推荐为主，算法决定冷启动 | 社交关系 + 算法推荐，朋友点赞会放大 |
| 内容气质 | 强钩子、快节奏、视觉冲击 | 信任、真实、教程、故事 |
| 适合目标 | 拉新、破圈、爆发式曝光 | 沉淀、转化、复购、私域 |
| 转化路径 | 视频 → 主页/合集 → 直播间/小程序 → 下载 | 视频 → 公众号文章 → 社群/企业微信 → 下载/付费 |
| 内容寿命 | 短，依赖持续更新 | 较长，可被转发到群/朋友圈 |
| 投放工具 | 千川/DOU+ | 微信广告/加热 |
| 关键指标 | 3 秒留存、完播、互动、主页点击 | 点赞/转发、公众号打开、社群进群 |

### 6.2 对 AirDeck 这类工具，内容应该怎么拍

AirDeck 的优势是“**5 秒内能看懂效果**”，非常适合短视频：

1. **3 秒钩子**：“你的 Windows 开始菜单，可以退休了。”
2. **15 秒爽点**：`Alt + Space` → 输入 `wx` → 微信秒开 → 再按 `Esc` 收回。
3. **30 秒视觉**：模糊壁纸 + 玻璃 Dock + 3D Cover Flow 展开。
4. **60 秒对比**：AirDeck vs 系统开始菜单 vs PowerToys Run（公平对比，不贬低）。
5. **系列化**：“100 个 Windows 效率工具”第 N 集；开发者 build log；“桌面改造 30 天”。
6. **搜索型标题**：“Win11 必装”“桌面太乱怎么办”“Windows 启动器推荐”。

**抖音适合：** 追求曝光和下载量，用强钩子 + 高频更新 + 投流放大。
**视频号适合：** 用开发者自述、用户案例、长教程建立信任，把观众导入公众号/社群，再做 Pro 转化。

### 6.3 对 WorkTop 的内容打法

WorkTop 比 AirDeck 多一个天然内容资产：**吉祥物**。

- **视觉钩子**：桌面上的能量球 → 单击展开环形菜单 → 双击召唤工作台。
- **情绪钩子**：“给桌面养一只会干活的小宠物。”
- **信任钩子**：“数据全部是本地 Markdown，Obsidian 可直接改，不上传。”
- **功能钩子**：“一句 AI 指令，把今天的待办排好。”
- **对比钩子**：“Notion 太重、便签太散，我把工作台放回桌面。”

内容配比建议：

| 平台 | 内容 | 频率 | 目标 |
|---|---|---|---|
| 抖音 | 15–30 秒桌面改造/吉祥物互动/效率挑战 | 3–5 条/周 | 拉新、测试钩子 |
| 微信视频号 | 1–3 分钟开发日志/用户故事/隐私理念 | 1–2 条/周 | 信任、私域 |
| B 站 | 5–10 分钟深度评测/从零搭建工作流 | 2–4 条/月 | 深度用户 |
| 小红书 | 桌面美学/卡片布局/壁纸搭配 | 3–5 条/周 | 女性/美学人群 |
| 公众号 | 版本更新、路线图、Pro 说明 | 每月 2–4 篇 | 留存、转化 |

### 6.4 从内容到付费的完整漏斗

```
短视频/视频号（兴趣）
   ↓
主页/合集/公众号（信任）
   ↓
官网下载（零门槛试用）
   ↓
首次使用时刻（Aha Moment）
   ↓
持续使用（Dock/卡片/吉祥物/快捷键）
   ↓
Pro 权益/企业服务（付费）
   ↓
用户案例/口碑（二次传播）
```

**关键：不要在下载前收钱。** 工具类产品应先让用户“用起来”，再在设置/账户里提供 Pro 入口。AirDeck 的「专业版体验」就是这种思路。

## 7. 对 WorkTop 的具体借鉴

### 7.1 定位：不要做“又一个启动器”

AirDeck 已经占据“原生启动台 + Dock”的生态位。WorkTop 的差异应该是：

> **本地优先的桌面工作台：把待办、导航、资产、凭据、速记、AI 和桌面宠物，放进一个可定制的桌面层。**

核心记忆点建议只保留一个：

- **“双击桌宠，召唤工作台”**（比“按快捷键”更有情绪、更适合视频传播）
- 辅助记忆点：“数据是你的 Markdown，不是别人的云。”

### 7.2 产品：借 5 个设计原则，不抄具体界面

| AirDeck 的做法 | WorkTop 可以怎么用 |
|---|---|
| 全局快捷键呼出 | 给 WorkTop 加一个 `Alt + Space` 快速唤起（可配置），提高使用频率 |
| 键盘优先搜索 | 工作台内搜索统一支持拼音首字母；卡片/应用/待办都能搜 |
| 场景化布局 | 增加“工作/生活/专注”场景，切换桌面卡片组合 |
| 配置迁移 | 一键导出/导入工作台布局、卡片、主题、快捷键 |
| 性能可量化 | 在官网/设置里展示真实启动耗时、内存占用、纯本地状态 |
| 3D 视觉惊喜 | 不必做 3D 窗口；把资源投入吉祥物动效、卡片转场、桌面氛围 |
| Dock 常驻 | WorkTop 已有 Dock，可强化“运行状态/一键收回”细节 |
| 小组件 | 继续做卡片，但避免“卡片越多越乱”；提供推荐布局 |

### 7.3 商业：AirDeck 的“免费 + Pro”不能照搬，因为 WorkTop 是 MIT 开源

这是一个关键差异：

- AirDeck 是闭源免费软件，可以自然地把高级功能锁进 Pro。
- WorkTop 代码以 MIT 开源，用户可以直接构建；**硬性功能阉割很难执行，也容易伤害社区信任**。

因此 WorkTop 更适合“**开放核心 + 付费便利/服务**”：

| 付费项 | 说明 | 适配度 |
|---|---|---|
| 签名安装包 + 自动更新 | 免去用户自己构建、解决 SmartScreen/升级麻烦 | 高 |
| 托管 AI 额度 | 用户不想自己配 API Key，愿意为“开箱即用”付费 | 高 |
| 高级主题/卡片/布局包 | 设计型付费，不影响核心代码 | 中高 |
| 优先支持/远程部署 | 个人用户和小团队都有人愿意为省时间付费 | 高 |
| 企业定制（业务卡片、私有部署、培训） | 与 README 的“定制”入口天然契合 | 最高 |
| 端到端加密的可选同步 | 技术复杂、成本高，适合后期 | 中 |
| 买断制 Pro 授权 | 若坚持闭源插件/云服务，可做 | 中 |

**推荐组合：**

```
免费开源核心（MIT）
  + WorkTop Pro 支持包（¥99–199/年 或 早鸟买断）
      - 签名安装包与自动更新
      - 托管 AI 额度（可选）
      - 高级主题/卡片包
      - 优先支持
  + 企业定制/部署服务（按项目报价）
```

这样既尊重开源许可，又有可持续收入，不会把“本地优先”变成“本地阉割”。

### 7.4 内容：把“开发者故事”做成长期资产

AirDeck 的微信公众号发布文章，是一个非常值得学的动作：不是冷冰冰的更新日志，而是讲“为什么做、怎么取舍、哪些细节”。WorkTop 可以：

- 每月一篇“桌面工作台开发日志”：新卡片、性能优化、踩坑。
- 每季度一个“用户工作台改造”案例：真实截图 + 使用场景。
- 把“本地优先/隐私”做成系列内容，而不是一句口号。
- 在视频号做直播答疑/共创，在抖音做短平快演示。
- 用吉祥物做固定 IP：表情包、壁纸、短视频片头。

### 7.5 90 天行动清单

| 阶段 | 动作 | 目标 |
|---|---|---|
| 第 1–2 周 | 官网/下载页埋点；确定 3 个核心卖点；拍 5 条不同钩子的短视频 | 找到能带来主页点击的钩子 |
| 第 3–4 周 | 发布 10–15 条抖音；同步 4 条视频号；上线“一键导入布局” | 验证内容-下载转化 |
| 第 5–6 周 | 内测 Pro 支持包（签名包/自动更新/AI 额度）；收集 50 份问卷 | 验证付费意愿 |
| 第 7–8 周 | 视频号直播答疑；发布 2 个用户案例；优化首启引导 | 提升激活与留存 |
| 第 9–10 周 | 定价实验（¥99/¥149/¥199）；企业定制页 | 找到价格锚点 |
| 第 11–12 周 | 复盘渠道 ROI；决定是否上 Microsoft Store；规划下一版本 | 形成可重复增长 |

### 7.6 建议追踪的指标

- 内容：3 秒留存、完播率、主页点击率、下载点击率。
- 产品：首次启动完成率、首个卡片创建率、D1/D7 留存、日均唤起次数。
- 商业：Pro 页面访问 → 试用 → 付费转化、客单价、退款率、企业线索数。
- 口碑：自然搜索量、用户推荐占比、社群活跃度。

## 8. 风险与边界

1. **不要照搬视觉资产**：可以学习“玻璃拟态/全屏启动台/场景化”的设计模式，但不要复制图标、插画、文案与具体版式，避免侵权与品牌混淆。
2. **不要为了 Pro 破坏核心体验**：AirDeck 的信任来自“免费、纯净”；WorkTop 若过早弹窗/限速，会损失本地优先的口碑。
3. **Windows 原生能力是双刃剑**：Hook、Dock、窗口捕获都受系统更新影响，需要测试矩阵与回滚机制。
4. **内容不能替代产品**：短视频能带来第一次下载，留存仍取决于首启体验、稳定性和真实效率提升。
5. **开源商业化要透明**：明确哪些是开源核心、哪些是付费服务，避免社区认为“假开源”。
